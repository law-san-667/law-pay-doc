Un bénéficiaire est un commerce de votre marketplace, identifié par un numéro
mobile money vers lequel LawPay reverse les paiements qui lui sont destinés.

**Authentification :** header `X-API-Key`. Le projet doit être en
[mode marketplace](/marketplace/overview/).

## Créer un bénéficiaire

```http
POST /api/v1/recipients
```

| Paramètre | Type | Requis | Description |
|-----------|------|--------|-------------|
| `name` | string | ✅ | Nom du commerce |
| `destinationNumber` | string | ✅ | Numéro mobile money qui reçoit les versements |
| `service` | string | ✅ | Opérateur : `"Orange Money Senegal"`, `"Wave Senegal"`, `"Free Money Senegal"`, `"Expresso Senegal"` |
| `externalId` | string | — | Votre propre identifiant du commerce, unique par projet. Permet de router un paiement avec `recipientExternalId` sans stocker l'id LawPay |
| `email` | string | — | Contact du commerce |
| `phone` | string | — | Contact du commerce |
| `metadata` | object | — | Données libres |

## Lister les bénéficiaires

```http
GET /api/v1/recipients?status=active&limit=50&offset=0
```

Retourne `{ recipients, total, limit, offset }`.

## Consulter un bénéficiaire

```http
GET /api/v1/recipients/:id
```

Inclut un objet `stats` : `paid_count`, `total_paid_out`, `failed_payouts`.

## Modifier un bénéficiaire

```http
PATCH /api/v1/recipients/:id
```

Tous les champs sont optionnels : `name`, `destinationNumber`, `service`,
`email`, `phone`, `status` (`active` | `suspended`), `metadata`.

<Aside type="caution">
  Un changement de `destinationNumber` ou de `service` redirige l'argent du
  commerce. Il est consigné dans le journal d'audit du projet et déclenche un
  webhook `recipient.updated` avec `destinationChanged: true`. Surveillez cet
  événement.
</Aside>

## Suspendre un bénéficiaire

```http
DELETE /api/v1/recipients/:id
```

Le bénéficiaire passe en `suspended` : les paiements existants restent
consultables, mais aucun nouveau paiement ne peut lui être destiné
(`RECIPIENT_SUSPENDED`) et les versements en échec ne sont plus réessayés.
Réactivez‑le avec `PATCH { "status": "active" }`.

## Erreurs

| HTTP | Code | Quand |
|------|------|-------|
| 400 | `MARKETPLACE_DISABLED` | Le projet n'est pas en mode marketplace |
| 400 | `VALIDATION` | Champ requis manquant ou `status` invalide |
| 404 | `NOT_FOUND` | Bénéficiaire inconnu pour ce projet |
| 409 | `CONFLICT` | `externalId` déjà utilisé dans ce projet |
